# 裁判评分与胜负判定规则（Skill 参考）

> 与代码同版本：`judge-rules/1.1.0`，引擎 `rule-based@1.0.0`（见 `packages/arena-core/src/engine/judge.ts`）。
> 裁判为确定性算法：同一 `(规则版本, 种子, 数据集指纹, 引擎版本, 验证结果)` 必得同一判定。
> **裁判不信任 Agent 自述成绩**——五维得分全部由 `verifyAgentProposal()` 基于当前数据集独立重算。

## 一、独立验证（打分前置）

| 检查 | 说明 |
|---|---|
| 餐品存在与在售 | 逐条核对编码是否在当前数据集、是否 `available` |
| 数量与重复 | 份数正整数；同一编码不得重复申报 |
| 预算 / 人数 / 种类 / 必选 | 硬约束，违反即 `fatal`（失去资格） |
| 优惠券 | 逐张校验存在性、门槛、标签、类型、是否重复申报，并由共享引擎重算优惠 |
| 价格核验 | 优先用官方 `calculate-price` 记录核价；无记录 → `not-verified`（**NOT_VERIFIED，不视为通过**） |
| 营养数据 | 缺数据记 `warning`，不剥夺资格 |

**价格核验状态**：`verified`（与官方一致）／`mismatch`（与官方不符，**以官方为准**）／`not-verified`（无官方记录）。
**成本依据 `costBasis`**：双方都有官方记录 → `official-verified`；否则 `claimed-unverified`。

## 二、五维评分（满分 100）

| 维度 | 满分 | 规则（全部基于裁判重算值） |
|---|---|---|
| 需求满足度 | 30 | 裁判校验通过项数 / 总项数 × 30 |
| 预算控制 | 25 | 裁决成本 ≤ 预算：`15 + 10 × 剩余比例`；未设预算：15；超预算：0；无有效成本：0 |
| 营养均衡 | 20 | 加权达成率 × 20（权重：热量 0.4 / 蛋白质 0.4 / 钠 0.2，按人数缩放）；无目标时中性 10 |
| 优惠利用 | 15 | 裁判重算优惠 / 券前应付 × 15（封顶） |
| 可解释性 | 10 | 证据完整度 40% + 独立校验说明覆盖率 60% |

## 三、胜负判定（严格字典序，先命中先返回）

1. **资格**：存在 `fatal` 违规即失去资格；双方都失格 → 平局。**无效方案不能凭低价取胜。**
2. **已验证成本**：双方都有官方核价 → 比官方成本；仅一方有 → 该方胜（另一方 `NOT_VERIFIED`）；双方都无 → 比裁判重算成本。
3. **营养 / 用户目标达成率**（成本相同时）。
4. **实际响应时间**（真实测量值，仅作最后手段；不写入复现指纹）。
5. 仍相同 → **平局**。

> 注意：胜负由上述字典序决定，**与五维总分不必然同向**。例如成本更低但营养分略低的一方仍可能获胜，
> 此时结论会明确标注「五维总分 X : Y」并给出判定依据，避免误读。

## 四、可复现

- `experimentId`（形如 `exp_xxxxxxxxxxxxxxxx`）由 `(规则版本, 种子, 数据集指纹, 引擎版本, 验证结果)` 派生；
- 同一配置重跑，`experimentId` 与全部确定性判定完全一致（实测耗时除外）；
- 输出中的 `reproducibleConfig` 可直接粘贴到网页「挑战设置」复现。
